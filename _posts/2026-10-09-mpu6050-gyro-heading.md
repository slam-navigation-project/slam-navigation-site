## 1. 진행 개요

- 엔코더 속도 제어만으로는 차체가 무거워 직진 시 조금씩 틀어지고, 바퀴 차이로 계산한 회전각(θ)도 미끄러짐에 취약함.
- MPU6050의 **z축 각속도**를 적분하여 θ를 측정.
- 직진 명령일 때 출발 방향을 자이로로 붙잡는 **방향 유지(Heading Hold)** 구현.
- 간헐적인 I2C 에러에도 제어가 멈추지 않도록 예외 처리.

### 장착 시 주의

- z축(칩 윗면에 수직인 축)만 사용하므로 **대략 수평**이면 충분하다. 몇 도 기울어진 정도는 오차가 작다 (cos 5° ≈ 0.996).
- 대신 차체에 **단단히 고정**해야 한다. 센서가 따로 흔들리면 그 흔들림도 회전으로 측정된다.
- 시작할 때 영점을 잡는 약 1초 동안은 차를 움직이면 안 된다.

## 3. 왜 엔코더가 아니라 자이로로 θ를 구하나

엔코더만으로도 회전각을 구할 수 있다.

```text
dθ = (dr − dl) / L      (L = 바퀴 간격)
```

하지만 이 식은 좌우 바퀴의 **작은 거리 차이**를 바퀴 간격(12cm)으로 나누기 때문에 오차가 크게 증폭된다.  
예를 들어 한쪽 바퀴가 1cm만 미끄러져도 `0.01 / 0.12 ≈ 4.8°`가 틀어진다.  
θ가 틀리면 그 뒤 이동한 거리 전부가 엉뚱한 방향으로 쌓이므로, θ는 **미끄러짐과 무관한 자이로**로 측정하였다.

| | 엔코더 차이 | 자이로 |
| --- | --- | --- |
| 미끄러짐 | 그대로 오차 | 영향 없음 |
| 바퀴 간격 측정 오차 | 회전량 전체에 비례 오차 | 영향 없음 |
| 단점 | - | 시간이 지나면 영점이 조금씩 흐름(드리프트), I2C 통신 필요 |

## 4. MPU6050 코드 (`MPU6050` 클래스)

### (1) 설정

```python
def wake(self):
    self.bus.write_byte_data(self.addr, self.PWR_MGMT_1, 0x00)   # 슬립 해제
    self.bus.write_byte_data(self.addr, self.CONFIG, GYRO_DLPF)  # 디지털 저역통과 필터
    self.bus.write_byte_data(self.addr, self.GYRO_CONFIG, 0x08)  # ±500 deg/s
```

**왜 이렇게 했나**

- **±500°/s**: 기본값 ±250°/s는 손으로 빠르게 돌리면 값이 잘린다(포화). 차는 그렇게 빨리 돌지 않지만, 테스트할 때 손으로 돌려도 안전하도록 한 단계 넓혔다. (65.5 LSB = 1°/s)
- **DLPF 0x04 (약 21Hz)**: 모터 진동은 빠른 떨림이라 센서 내부에서 걸러 낸다. 차의 실제 회전은 느리므로 손해가 없다.
- **`wake()`를 함수로 분리**: 전압 강하로 센서가 리셋되면 슬립 상태로 돌아가 0만 나온다. I2C 에러가 계속되면 이 함수를 다시 불러 재설정한다.

### (2) 영점(바이어스) 보정

```python
def calibrate(self, samples=300):
    total = 0
    for _ in range(samples):
        total += self._raw_z()
        time.sleep(0.003)
    self.bias = total / samples
```

자이로는 가만히 있어도 0이 아닌 값(예: 0.5°/s)이 나온다.  
이걸 그대로 적분하면 **가만히 있어도 1분에 30°씩 돌아간 것으로** 계산된다.  
시작 시 약 1초간 평균을 내어 매번 빼 준다.

## 5. 각도 적분 (`_gyro_loop`)

```python
def _gyro_loop(self):
    """200Hz로 자이로를 읽어 사다리꼴 적분. 빠른 회전도 놓치지 않게 제어 루프와 분리."""
    while self._running:
        time.sleep(GYRO_DT)                       # 5ms
        ...
        rate = self.imu.rate_z() * GYRO_SCALE
        ...
        self._gyro_yaw += 0.5 * (rate + prev_rate) * dt
        prev_rate = rate
```

**왜 이렇게 했나**

- **별도 스레드, 200Hz**: 각도는 각속도를 시간에 대해 더한 값이라, 띄엄띄엄 읽으면 그 사이에 변한 부분을 놓친다. 제어 루프(50Hz)와 분리해 4배 빠르게 읽었다.
- **사다리꼴 적분**: `현재 값 × dt` 대신 `(이전 + 현재)/2 × dt`로 더하면 속도가 변하는 구간(회전 시작/끝)의 오차가 줄어든다.
- **`GYRO_SCALE = 360/350`**: 실제로 한 바퀴(360°) 돌렸을 때 화면이 350°로 나와서 비율을 곱해 보정하였다.
- **`GYRO_Z_SIGN`**: 차체 기준은 반시계 방향이 +이다. `A`(좌회전) 했을 때 θ가 증가하는지 확인하고 부호를 맞추었다. 이 부호가 틀리면 아래 방향 유지가 **오차를 키우는 방향으로** 동작해 차가 한쪽으로 계속 돌아 버린다.

### 제어 루프에서 사용 (`_gyro_dtheta`)

```python
def _gyro_dtheta(self, dt, dl, dr):
    enc_dth = (dr - dl) / TRACK_WIDTH
    if self.imu is None:
        return enc_dth
    yaw = self._gyro_yaw
    d = yaw - self._prev_gyro_yaw
    self._prev_gyro_yaw = yaw
    if time.monotonic() - self._gyro_last_ok > 0.1:
        return enc_dth                      # 자이로가 0.1초 이상 끊기면 엔코더로 대체
    return d
```

제어 루프는 매 주기 **자이로 누적각의 변화량**만 가져다 θ에 더한다.  
자이로가 끊긴 동안에는 엔코더로 계산한 회전각으로 대신해서, θ가 멈추지 않게 하였다.

## 6. 직진 유지 (Heading Hold)

### (1) 언제 켜지나

```python
def set_velocity(self, v, omega):
    ...
    if new_target == self.target:
        return                               # 같은 명령 반복: 기준을 초기화하지 않음
    hold = (omega == 0.0 and v != 0.0)       # 회전 명령 없이 전진/후진일 때만
    if hold and not self.hold_heading:
        self.heading_target = self.theta     # 직진이 시작되는 순간의 방향을 기억
    self.hold_heading = hold
```

- 회전 명령(ω) 없이 전진/후진할 때만 켠다.
- **같은 명령이 반복해서 들어오면 무시**한다. 키보드 조종 노드가 0.1초마다 같은 명령을 다시 보내는데, 그때마다 "출발 방향"을 현재 θ로 다시 잡으면 조금씩 틀어진 방향이 계속 새 기준이 되어 보정이 무의미해진다.

### (2) 보정 과정

```python
if self.hold_heading and self.imu is not None:
    err = wrap_angle(self.heading_target - self.theta)
    corr = max(-HEAD_CORR_LIMIT, min(HEAD_CORR_LIMIT, K_HEAD * err))
    tl_adj = tl - corr      # 왼쪽으로 틀어지면(err < 0) 왼쪽 빠르게
    tr_adj = tr + corr      #                          오른쪽 느리게
```

0.02초마다 다음을 반복한다.

```text
① 자이로로 현재 방향 θ 갱신
② 오차 = 출발 방향 − 현재 θ
③ 보정량 = K_HEAD × 오차          (최대 HEAD_CORR_LIMIT)
④ 왼쪽 목표 = 기본 − 보정량,  오른쪽 목표 = 기본 + 보정량
⑤ 각 바퀴의 PI 제어기가 그 목표 각속도를 내도록 PWM 결정 (1편)
⑥ 모터 구동 → 다시 ①
```

**숫자 예시** (전진 0.05 m/s → 바퀴 기본 목표 약 1.05 rad/s, `K_HEAD = 2.0`)

1. 차체 무게 때문에 왼쪽으로 2° (0.035 rad) 틀어짐
2. 오차 = 0 − 0.035 = −0.035 rad
3. 보정량 = 2.0 × (−0.035) = −0.07 rad/s
4. 왼쪽 목표 = 1.05 + 0.07 = **1.12**, 오른쪽 목표 = 1.05 − 0.07 = **0.98**
5. 왼쪽이 더 빨리 돌아 차가 오른쪽으로 돌아옴
6. 돌아올수록 오차와 보정량이 0에 가까워지고 두 바퀴 속도가 다시 같아짐

### (3) 특징

- 좌우로 크게 왔다 갔다 하는 방식이 아니라, **틀어진 만큼 비례해서** 부드럽게 되돌린다.
- 차체가 한쪽으로 계속 끌리면(무게 쏠림, 바퀴 마찰 차이) 그걸 버티느라 **직진 중에도 두 바퀴 각속도가 계속 조금 다르다.** 고장이 아니라 보정이 일하고 있다는 뜻이다.
- 방향(각도)만 바로잡는다. 틀어졌다 돌아오는 동안 이미 옆으로 밀린 거리(수 mm ~ cm)는 되돌리지 않으므로, 차는 출발선과 **평행하게 살짝 비켜서** 간다. 대신 오도메트리가 그 밀린 거리까지 기록하므로 SLAM에는 문제가 없다.
- **`K_HEAD` 4.0 → 2.0으로 낮춘 이유**: 저속(기본 1.05 rad/s)에서 보정량이 기본 속도보다 커지면 한쪽 바퀴가 멈추거나 거꾸로 돈다. 그러면 오히려 크게 꺾이며 흔들렸다.

### (4) 명령 종류별 보정 방식 정리

`_step()`은 명령에 따라 세 가지 중 하나를 쓴다.

| 명령 | 보정 방식 | 이유 |
| --- | --- | --- |
| 직진 / 후진 | **자이로 방향 유지** | 목표가 "방향"이므로 방향을 직접 측정해 보정 |
| 곡선 주행 (v, ω 둘 다) | 바퀴별 속도 제어만 | 좌우 속도가 원래 달라야 하므로 동기화하면 안 됨 |
| 제자리 회전 | 좌우 누적 회전량 동기화 | 두 바퀴가 같은 양만큼 반대로 돌아야 제자리에서 돎 |

## 7. I2C 에러 대응

### (1) 증상

주행 중 **직진/후진할 때만** I2C 읽기 에러(`OSError`)가 발생하였다. 제자리 회전 중에는 발생하지 않았다.  
초기 코드에서는 이 에러로 **제어 스레드가 죽어 모터가 계속 도는** 위험한 상황이 생겼다.

### (2) 원인 추정과 확인

처음에는 모터가 돌 때 생기는 전기적 노이즈가 전원을 타고 I2C 선에 들어오는 것으로 추정하였다.  
그래서 모터 드라이버 전원을 **9V 배터리로 따로 분리**해 보았으나, **에러는 그대로 발생**하였다.

→ 전원 노이즈가 원인은 아닌 것으로 판단하고, 모터 드라이버 전원은 다시 **라즈베리파이 5V**로 되돌렸다.

정확한 원인은 아직 찾지 못하였다. 다만 다음과 같은 특징이 있어 당장 문제가 되지는 않는다.

- 직진/후진 중에만 끊기고, 잠시 뒤 **자동으로 다시 연결**된다.
- 직진/후진 중에는 차가 거의 회전하지 않으므로, 끊긴 동안 놓치는 회전량이 매우 작다.
- 각도의 기준(처음 방향 0°)과 누적값 θ는 센서가 아니라 **코드 변수에 저장**되어 있다. 자이로는 "지금 몇 °/s로 도는지"만 알려 주므로, 다시 연결되어도 θ는 끊기기 직전 값에서 그대로 이어진다.

그래서 우선은 아래 코드로 에러를 견디도록만 처리하고 넘어갔다.

### (3) 대응 코드

```python
try:
    rate = self.imu.rate_z() * GYRO_SCALE
except OSError as e:
    self.i2c_errors += 1
    streak += 1
    if streak % 20 == 0:
        self.imu.wake()          # 센서가 리셋됐을 수 있으니 재설정
    if streak > 3:
        prev_rate = 0.0
        continue                 # 길게 끊기면 적분 중단 (제어 루프가 엔코더로 대체)
    rate = prev_rate             # 짧은 끊김은 직전 각속도로 메움
else:
    streak = 0
    dps = math.degrees(rate)
    if abs(dps) > MAX_GYRO_DPS or abs(dps - math.degrees(prev_rate)) > MAX_GYRO_JUMP_DPS:
        rate = prev_rate         # 노이즈로 깨진 값 -> 직전 값으로 대체
```

| 상황 | 처리 | 이유 |
| --- | --- | --- |
| 짧은 끊김 (3회 이하, 15ms) | 직전 각속도로 메움 | 15ms 동안 회전 속도는 거의 안 변함 |
| 긴 끊김 | 적분 중단, **엔코더 회전각으로 대체** | 틀린 값을 계속 더하는 것보다 엔코더가 나음 |
| 20회 연속 실패 | `wake()`로 재설정 | 센서가 리셋되어 슬립 상태일 수 있음 |
| 300°/s 초과, 5ms에 150°/s 이상 변화 | 깨진 값으로 보고 버림 | 차가 물리적으로 낼 수 없는 값 |

제어 루프(`_loop`)에도 `try/except`를 걸어, 어떤 예외가 나도 **스레드는 살아 있고 모터는 정지**하도록 하였다.

```python
try:
    prev_l, prev_r = self._step(dt, prev_l, prev_r)
except Exception as e:
    self.last_error = f"{type(e).__name__}: {e}"
    self.target = (0.0, 0.0)
    motor_left.stop()
    motor_right.stop()
```

I2C 에러의 정확한 원인은 차체를 다시 만들면서 배선을 정리한 뒤 다시 확인할 예정이다.

## 8. 결과

- 여러 바퀴 회전시키고, 중간에 선이 꼬여 손으로 제자리에 돌려놓아도 **약 2° 오차** 수준으로 θ 유지.
- 직진 시 방향 유지로 휘는 현상 크게 감소.
- I2C 에러가 나도 주행이 멈추지 않고 자동 복구.
